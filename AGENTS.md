# AGENTS.md

PLCVM — the "Pension" app. Expo SDK 57 (React Native 0.86, React 19.2) managed
workflow, TypeScript strict, expo-router file-based navigation, pnpm.

**This repository is a single app — the root _is_ the project.** There is no
`apps/` or `packages/` workspace. It was a pnpm monorepo until the
`refactor/single-repo-plcvm` branch; the shared packages are now plain
directories under `src/shared/`. Do not reintroduce workspace scaffolding.

No native `ios`/`android` dirs in the repo (generated by EAS/prebuild).

## Commands

| Command                                                                              | What it does                                                   |
| ------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| `pnpm dev`                                                                           | Start Metro dev server (`expo start --clear --localhost`)      |
| `pnpm test` / `pnpm test:watch` / `pnpm test:coverage`                               | Jest via jest-expo                                             |
| `pnpm lint`                                                                          | ESLint + Prettier + `tsc --noEmit`, chained (warnings allowed) |
| `pnpm format`                                                                        | ESLint `--fix` + Prettier `--write`                            |
| `pnpm typecheck` / `npx tsc --noEmit`                                                | Typecheck                                                      |
| `pnpm clean`                                                                         | Remove every `node_modules` under the repo root                |
| `node scripts/generate-feature.js`                                                   | Scaffold a new feature slice                                   |
| `pnpm preview` / `pnpm preview:local`, `pnpm development` / `pnpm development:local` | EAS Android APK builds                                         |

Verify with `npx tsc --noEmit` → `pnpm test` → `npx eslint` → `npx prettier -c`.
A production-shaped check is `npx expo export --platform android`; it exercises
Metro's own alias resolution, which `tsc` does not.

## Layout

- `src/app/` — expo-router routes. Root `_layout.tsx` mounts `ProviderWrapper`
  (gesture-handler, safe-area, root-detection gate, query client, auth,
  redirects). Files here map directly to routes — no central nav config.
- `src/features/<feature>/` — feature slices: `components/`, `hooks/`,
  `screens/`, `store/` (zustand), `types/`, `utils/constants/`,
  `validators/` (zod). These folders have no barrel `index.ts`; import the
  concrete file (e.g. `@features/login/validators/login`).
- `src/shared/` — cross-cutting, one directory per concern:
  `api/` (axios factory + response handling), `components/` (`ui`, `layout`,
  `common`, `screens`, `providers`), `config/`, `hooks/`, `lib/encryption`,
  `stores/` (zustand), `types/` (`api`, `auth`, `page`, `tab`), `utils/`
  (`constants`, `helpers`, `http`, `logger`, `react-query`), `validation/`
  (shared zod schemas).
- `expo-config/` — build-time Expo config. Plain Node, evaluated only by
  `app.config.ts`; never bundled. Kept out of `src/` so Metro cannot reach it.
- `test/setup.ts` — Jest setup and the native-module mock layer.
- `http/` — REST scratch client (`.http` files), not part of the bundle.

## Conventions

- Use tsconfig path aliases, and always import the **concrete file**, never a
  re-export barrel: `@api` (the one remaining bare alias — it holds the real
  `createApi` implementation), plus the wildcard forms `@api/*`, `@assets/*`,
  `@components/*`, `@config/*`, `@features/*`, `@hooks/*`, `@lib/*`,
  `@sharedTypes/*`, `@stores/*`, `@styles/*`, `@utils/*`, `@validation/*`.
  Avoid relative imports across slices. There is no bare `@components`,
  `@config`, `@hooks`, `@lib`, `@sharedTypes` or `@utils` alias — those barrels
  were deleted; add the explicit file to the wildcard path instead
  (e.g. `@components/ui/button`, not `@components`).
- **Inside `src/shared/components/`, import the specific sibling file**
  (`../ui/button`, `../common/ternary`, `../screens/error-screen`), not a
  directory. The top-level `@components` barrel is gone, and reintroducing a
  directory-level barrel would create an import cycle, since a barrel
  re-exporting the tree it lives in imports itself.
- **Keep native-API and configured-HTTP modules behind their own subpath.**
  Code that runs under Jest has no native runtime, so anything pulling in
  `expo-file-system`/`expo-sharing`/`expo-sharing` (e.g.
  `helpers/save-base64-pdf`) or the configured axios client must be imported
  directly (`@utils/http/client`), never swept into a shared barrel.
- Styling: NativeWind 4 (Tailwind) via `className`. Keep `babel.config.js`
  intact — `react-native-worklets/plugin` is required by reanimated/worklets,
  and the `nativewind` jsx import source.
- API paths: reference `ENDPOINTS`
  (`src/shared/utils/constants/endpoints.ts`) — never hardcode URL strings.
  The app-wide axios client is `src/shared/utils/http/client.ts` (JSON; attaches
  the Bearer token and Fernet-encrypts object payloads; resolves auth-path errors
  to the caller; no automatic 401 token refresh).
- JSDoc all exported functions/hooks/components (repo-wide style). Commits are
  Conventional Commits.
- New features: `node scripts/generate-feature.js` scaffolds the slice, then
  wire the screen into `src/app/`.

## Environment

- Env vars are `EXPO_PUBLIC_*`, inlined at build time:
  `EXPO_PUBLIC_API_URL` (main API), `EXPO_PUBLIC_DAT_API_URL` (pension
  statements), `EXPO_PUBLIC_FERNET_KEY` (payload encryption),
  `EXPO_PUBLIC_PPO_NO`, `EXPO_PUBLIC_TEST_IMAGE`.
- Dev requires a local `.env` (copy `.env.sample`); `API_BASE_URL` reads
  `EXPO_PUBLIC_API_URL` and is undefined without it.
- `APP_VARIANT` (injected by `eas.json` profiles) drives the bundle ID suffix,
  app display name, and allows cleartext HTTP only outside production.
- pnpm blocks native module postinstall scripts by default: new deps needing
  them must be added to `allowBuilds` in `pnpm-workspace.yaml` (or
  `pnpm.onlyBuiltDependencies` in `package.json`).
- `pnpm-workspace.yaml` carries pnpm settings only — there is deliberately no
  `packages:` list. The `packageExtensions` entries are load-bearing: without
  `nativewind`'s `react-native` peer or `react-native-css-interop`'s `connect`
  dependency, `expo start` fails to resolve.

## Testing

- Jest only collects `*.test.ts` under `src/features/**/test/**` and
  `src/shared/**/test/**` — tests go in `test/` folders, not `__tests__/` or
  colocated. Shared tests live in `src/shared/test/`.
- Suites cover zod validators, zustand stores, hooks, and components, using
  `renderHook`/`render`/`waitFor` from `@testing-library/react-native`.
- `test/setup.ts` holds the **global native-module mock layer**: expo-router,
  expo-updates, expo-location, expo-secure-store, expo-sharing,
  expo-file-system, expo-application, expo-device, expo-crypto,
  expo-image-manipulator, expo-splash-screen, expo-status-bar, expo-linking,
  expo-screen-capture, jail-monkey, react-native-pdf and the vision-camera
  packages. **Any new native module imported by a shared component must be
  mocked there**, otherwise every suite reaching that component through a
  barrel fails at import time. Per-suite overrides are fine and preferred when
  a test needs real behaviour.
- Keep the `transformIgnorePatterns` allowlist in `jest.config.js` — the
  `.pnpm` entry is required for pnpm's symlinked node_modules under jest-expo.

## Security (production-critical)

- `RootProvider` / `useRootDetection` (`jail-monkey`) blocks jailbroken/rooted
  devices and debugger-attached processes in production; bypassed in `__DEV__`
  and fails closed. Do not weaken the gate.
- `usePreventScreenCapture()` is mounted globally in `ProviderWrapper` — keep it.
- Sensitive request payloads are Fernet-encrypted
  (`src/shared/lib/encryption`, key from `EXPO_PUBLIC_FERNET_KEY`).
- The keychain is for **secrets only** — the session tokens in
  `stores/token.store.ts`. Stores call `expo-secure-store` directly; there is no
  persistence wrapper layer, so each store owns its own keychain reads and
  writes. Keychain keys are dot-namespaced (`pension.*`) because the native API
  rejects colons, and those literals are a compatibility contract: changing one
  logs every signed-in user out on upgrade. SecureStore is a keychain entry, not
  a database — values above ~2 KB are unsuitable on Android, so do not use it
  for bulk or frequently rewritten state.
- Cleartext HTTP is disabled in production
  (`usesCleartextTraffic: false` in `expo-config/build-properties.ts`).
